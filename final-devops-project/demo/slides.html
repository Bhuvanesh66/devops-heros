Project overview

What I built

The application

  • A task tracker: title, description, priority, due date
  • Tasks move to do → in progress → done
  • Filters by status and live counters (per status, open high-priority)
  • REST API with full CRUD, health, readiness and metrics

The real goal: the delivery chain

  • Tests and security scans gate every commit
  • Images tagged with the commit SHA in GHCR
  • Terraform builds the AWS VPC and EKS
  • Helm and Argo CD deploy to Kubernetes
  • Prometheus and Grafana watch it run

TaskFlow · DevOps Capstone4

CI/CD flow

GitHub Actions: every push to main

git push→ Lint + pytest + frontend build→ Validate IaC→ SAST · SCA · Secret scan→ Docker build + smoke test→ Trivy image scan + SBOM→ Security gate→ Push to GHCR :<sha>→ Helm deploy + helm test

Tests gate the build

A failing test stops the pipeline. No image is built or pushed.

SHA tags, not latest

Every image traces back to one exact commit, which makes rollback precise.

Scanned = shipped

The tar Trivy scanned is the one pushed. Image IDs are checked before push.

Dependencies (SCA)pip-audit, npm audit, Trivy fs0 vulnerabilities
SecretsGitleaks: files + git historyno leaks
Frontend imageTrivy0 HIGH / CRITICAL
Backend imageTrivy44 HIGH, 0 fixable

The 44 HIGH are all Debian 13 base packages (util-linux, perl…) with no upstream fix yet, e.g. CVE-2026-76642. The gate blocks any HIGH/CRITICAL with a fix. The app runs as non-root and never calls mount.

TaskFlow · DevOps Capstone6

Infrastructure as Code

Terraform on AWS (ap-south-1)

  • VPC 10.20.0.0/16 with an Internet Gateway
  • 2 public subnets in ap-south-1a and 1b
  • EKS 1.34 cluster with a managed node group
  • EBS CSI add-on so Postgres gets a volume
  • EC2 Docker host (IMDSv2, encrypted disk) + S3 bucket
  • IAM roles with only the AWS-managed policies needed

Workflow

init → fmt → validate → plan → apply → destroy

No secrets in Git

Credentials come from the AWS CLI. Only terraform.tfvars.example is committed.

Cost control

EKS is not free tier, so it's created for the demo and destroyed right after.

TaskFlow · DevOps Capstone8

GitOps

Argo CD: Git is the source of truth

Change image tag in values-dev.yaml→ git push→ Argo CD detects the change→ Sync to cluster
  • Automated sync with prune and self-heal: a Service deleted by hand came back in 2 seconds
  • Rollback = git revert, with a full audit trail in Git history
  • Fixed a permanent OutOfSync on the Postgres StatefulSet with ignoreDifferences on volumeClaimTemplates

TaskFlow · DevOps Capstone11

Key learnings

What building it for real taught me

  • Readiness ≠ liveness. If liveness checked the DB, one Postgres hiccup would restart every pod at once.
  • Only a real apply proves IaC. IAM and S3 rejected brackets in a tag that EC2 accepted, and validate couldn't catch it.
  • Account limits matter. An AWS Free-plan account refuses t3.medium, so the EKS node group hung until I switched to m7i-flex.large.
  • Scanners report, the gate decides. A missing report counts as a failure, so the gate can't pass by accident.
  • GitOps and immutable fields. API-server defaults in a StatefulSet kept Argo CD OutOfSync. The fix came from diffing the state, not from syncing again.
